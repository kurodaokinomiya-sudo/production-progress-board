# 生産工程管理

ローカルブラウザー検証は [開発用QA手順](docs/browser-qa.md) を参照してください。`npm ci`、`npm run qa:install`、`npm run qa` で、専用ポートと隔離デモ状態の検証を実行できます。

現在のGoogleスプレッドシートをデータ基盤として残し、PC・タブレットのブラウザから使う工程管理Webアプリです。

ローカル実行にはNode.js 22.13.0以降の22系、または24以降が必要です（23系は対象外）。Node.js 24系を推奨します。依存関係はロックファイルに固定しており、初回は `npm ci` で導入します。Windows PowerShellでは `npm.cmd`、macOS・Linuxでは `npm` を実行してください。実行確認済み環境と未検証範囲は [開発用QA手順](docs/browser-qa.md#検証の限界) に記載しています。

注文メールと注文画像は、直接案件へ登録せず「取込キュー」へ入ります。読み取った得意先・品名・納期・数量・連番・仕様・大分類を人が確認してから案件へ反映するため、OCRの誤読がそのまま製作指示になりません。

## できること

- 編集者以上の「Tezoe製品在庫」で、確定受注の自動反映、重複しない在庫確保、先出し／一括の出荷予定、製造・補充と受注を加味した将来在庫、製造ロット別の入出庫と出荷元を共有します（[Tezoe製品在庫](docs/Tezoe製品在庫.md)）
- 編集者以上の「碓井材料在庫」で、碓井仕入の慈大式彫骨器・Tezoeの現在庫、発注残、入庫予定、発注・入庫・使用履歴を共有。注文確定時に1丁につき1セットを差し引き、一部入庫・在庫調整にも対応します（[材料在庫管理](docs/材料在庫管理.md)）
- 納期と工程残数による優先キュー
- 溶接 → 元作り → 浮き止め～立ち上がり → 厚みとり → 仕上げ → 出荷の進捗管理
- 工程一覧はケリソンパンチ、鋭匙鉗子の順に上下へ分けて表示。鋭匙鉗子の「厚みとり」は「頭付け・幅取り」と表示
- 一覧の工程を押し、ボタンで状態と担当を続けて選択。担当・状態を長押しして上に出る「全」へスライドすると全工程へ入力（キーボードは Alt＋↑）。直前の一括変更は元に戻せます
- 「工程を保存」を押すとすぐ一覧へ戻り、通信に失敗した場合は「入力内容を開く」から再確認できます
- 編集者以上は工程一覧の「研」で案件の全数を研磨中にし、「研磨管理表」で発送・戻りを記録できます。発送日・数量は工程一覧と研磨管理表に表示され、発送・戻り・履歴訂正は全端末で共有し、スプレッドシートの「工程管理_研磨」にも反映します。作業員には「研」ボタンと研磨管理表を表示しません。研磨へ出した案件は全数量が戻るまで最終仕上げを完了にできません
- 工程一覧と完成品リストの「33製品」は通常表示、「23製品（簡易view）」は上部と備考以降を省いた拡大表示です。指定した製品数を目安に高さへ合わせ、倍率欄へ40〜160%を直接入力することもできます。「33製品」で通常表示へ戻せます。倍率・表示モードは端末内に保存し、再起動後も使う想定です
- 「設定 → 工程ごとの担当候補」で、10名（豊・幹・望・鈴・河・誠・小・保・大・順）の表示を工程別に設定。全端末で共有し、登録済みの担当は保持
- 通常の「仕上げ」工程には完了操作がありません。「最終仕上げ」の完了操作は、研磨へ実数量の全数を発送し、その全数が戻った後だけ使えます。未発送・一部発送・未返却のまま通常操作や一括操作で完了にすることはできません。最終仕上げ完了後は先行工程が未完了でも工程一覧から「完成品リスト」の上段（出荷待ち）へ移ります。作業員は出荷待ち・完成品リストを閲覧でき、出荷完了・再開は編集者・管理者・所有者が行います。完成品リストの出荷待ちで出荷完了にすると完成品リストへ移り、再開すると出荷待ちへ戻ります。条件を満たさず誤って完了扱いになった未出荷案件は工程一覧に残るか戻り、作業員が工程を更新できます。案件全体を一括リセットしません。
- 今月完了した案件数と、各工程の担当者を一覧表示
- 得意先・品名・大分類・連番・担当者の検索、現在工程の絞り込み
- 初期表示は得意先順（田中が先頭、その他の得意先は逆順、在庫・在庫用は末尾）。優先順・大分類・連番・納期・更新日時へも並び替えられます
- 品名中の語から大分類を自動判定（ケリソン／スタンツェ／スタンチェ／彫骨器 → ケリソンパンチ、鉗子 → 鋭匙鉗子）
- 誤登録した案件は一覧から削除でき、直後なら元に戻せます。シートの行は物理削除せず操作履歴を残します
- 品名中の全長・型・刃幅を空欄へ自動補完（人が入力した値は上書きしません）
- メール・画像の確認反映後に製品ラベルを自動で「印刷待ち」へ追加し、最大9件をA4縦へ一括印刷
- Google Workspaceの独自ドメインメール、またはGmailへ転送した注文メールの候補検索（メールの削除・移動・既読化はしない）
- JPEG・PNG・WebP・PDFの文字読取（Google Drive OCR）
- 取込候補を編集しながら個別削除・選択削除（全選択・全解除、削除前の確認付き）
- 「得意先をミズホにして」で選択した取込候補をまとめて修正し、次回のAI読取に使う発注元の表記・御社名の除外ルールを保存
- 田中医科の `TC_26_1790` 形式など、1枚に複数品目がある発注書を品目ごとの取込候補へ分割
- ローカルWebアプリでも文字入りPDFを実解析（`npm run dev`で起動。写真・画像だけのPDFはApps Script版OCRを使用）
- 既存の月別シートを変更せず、アプリ用シートへ複製
- 保存直後の反映、20秒ごとの再同期、更新番号による競合検知
- PCでは表、タブレット／スマートフォンではカードへ自動切替
- 端末設定に合わせる／ライト／ダークの表示切替

## まず画面を確認する

Node.js 24系を推奨します。Node.js 22系を使う場合は22.13.0以降を使用してください。リポジトリのルートで依存関係を導入してから開発サーバーを起動します。

```powershell
npm.cmd ci
npm.cmd run dev
```

macOS・Linuxでは `npm ci` と `npm run dev` を実行します。

ブラウザで `http://127.0.0.1:4173` を開きます。ローカル版は「デモデータ」と表示され、Googleの実データには接続しません。解析コードを更新した後は、起動中のサーバーをいったん止めて同じコマンドで再起動してください。画面と解析サーバーの版が違う場合は、誤った候補を保存せず再起動案内を表示します。

## タブレットのホーム画面から使う

AndroidはGoogle Chromeで[本番Webアプリ](https://script.google.com/macros/s/AKfycbwVlF96mdaxEptRwXWeh2oAZ0-s0INe6jMHaB1BWhImXd8x_hbn7hSKcpMY7v2ERzJmpA/exec)を開き、利用するGoogleアカウントで工程一覧まで進みます。Chromeのメニュー「⋮」→「インストールしてショートカットを作成」→「ショートカットを作成」→「追加」で、ホーム画面へ「生産工程管理」を追加します。Chromeのバージョンによっては「ホーム画面に追加」と表示されます。更新前に作ったアイコンがブラウザのタブで開く場合は、そのアイコンをホーム画面から外して作り直します。アプリのデータは消えません。

「ショートカットを作成」でもインストールエラーになる端末では、[通常のChromeショートカット用URL](https://script.google.com/macros/s/AKfycbwVlF96mdaxEptRwXWeh2oAZ0-s0INe6jMHaB1BWhImXd8x_hbn7hSKcpMY7v2ERzJmpA/exec?launch=browser)から追加を試してください。このURLは専用画面での起動設定を省いて、Chromeの通常のブックマーク用ショートカット経路を使用します。本人確認後もこのURLを保ちます。

Android Chromeのホーム画面から専用画面で開くための `mobile-web-app-capable` と、iPad用の `apple-mobile-web-app-capable` を、Apps Scriptの `doGet()` で配信ページへ設定しています。HTMLファイル内へのメタタグ追加だけでは、Google側の外枠へ反映されません。iPadはSafariの「共有」→「ホーム画面に追加」を使用します。iPadのホーム画面WebアプリはSafariとは別の保存領域を使います（[Appleの説明](https://developer.apple.com/videos/play/wwdc2023/10120/?time=253)）。一覧の倍率・表示モードは端末内に保存して再起動後も使う想定です。繰り返し初期値へ戻る動作は仕様ではありません。

これは現在のApps ScriptのURLを使うホーム画面用の対応です。通信と従来のGoogleログイン・本人確認が必要で、オフライン対応やPlayストアへの登録は行いません。どちらのURLもアイコンの追加にはAndroidのホーム画面アプリの対応と許可が必要で、端末の制限をこのWebアプリから変更することはできません。追加に失敗する場合は、機種、Android・Chromeのバージョン、エラー全文と、エラーが「追加」の前後どちらで出るかを確認します。実機でアイコンの追加、起動、工程の保存を確認してください。

参考: [Chromeのショートカット作成手順](https://support.google.com/chrome/answer/15085120?co=GENIE.Platform%3DAndroid&hl=ja)、[Apps Scriptの配信ページのメタタグ](https://developers.google.com/apps-script/reference/html/html-output#addMetaTag(String,String))、[Chromiumのホーム画面起動処理](https://chromium.googlesource.com/chromium/src/+/88d7b2e74349cbf8b3e15b61cc0663d65f9d1873/components/webapps/browser/android/add_to_homescreen_data_fetcher.cc#176)。

## 工程一覧を広く見る

起動時は、未出荷の製品を1製品1行で表示する工程一覧を開きます。タブレットも表形式で、上部メニューは一列です。「33製品」で画面の高さに合わせて縮小し、「23製品（簡易view）」で上部と備考以降を省いた拡大表示にできます。倍率欄へ40〜160%を入力して調整できます。各大分類の表の下に案件数と数量の小計、すべての表の下に表示中の総合計を表示します。倍率・表示モードは端末内に保存し、再起動後も使う想定です。iPadのホーム画面WebアプリとSafariでは保存領域が別です。保存値が繰り返し消えるのは意図した動作ではありません。

起動中は読み込み画面を表示し、通信に失敗した場合はその場で再試行できます。注文・工程の保存、案件や取込候補の削除、研磨発送・戻り、配布担当の変更は画面へ先に反映し、通信中も別の案件を操作できます。「研」は対象行に「研 反映中…」、画面下には処理中の件数を表示します。同じ案件への変更は完了まで保留します。通信に失敗した変更は元の表示へ戻し、注文・工程の入力や研磨の再試行内容を保持します。完了まではタブを閉じないでください。新規注文と研磨の再試行には同じ識別子を使い、二重登録・二重計上を防ぎます。

表の上を2本指でピンチすると拡大縮小します。PCはCtrl（Macは⌘）＋ホイール、または倍率欄の上でホイールを使います。通常のホイールや1本指はスクロールです。表が画面幅に収まる倍率では縦方向だけに動き、拡大して横に収まらなくなったときだけ横スクロールできます。倍率の範囲は40〜160%で、小さい画面では33行に満たない場合があります。

製品名を押すと省略のない詳細、工程の担当・状態を押すと従来の編集画面を開きます。「検索・絞り込み・並び順」は必要なときに開きます。自動更新時も一覧のスクロール位置を保ち、表示するデータや権限が同じときは表を作り直しません。ピンチ操作中の自動更新は次回へ回します。完成品リストでも同じ表示操作を使えます。

## 鋭匙鉗子の担当を割り振り、配布表を印刷する

「担当・配布表」で納期の月を選び、「表示する担当者を設定」から候補を選ぶと、設定が全端末で共有されます。案件ごとに担当者名を選ぶと工程担当とは別に配布担当が保存され、「未定」で解除できます。候補から外した担当者の既存割当はそのまま残り、案件と集計に表示されます。

一覧は納期順または得意先順で並べ替えられます。得意先順では同じ得意先の中を納期順に表示します。担当者別の合計丁数は一覧下に表示され、選択月の全担当を集計します。担当者で絞り込んでも合計は全担当分を保ち、出荷完了のチェック状態を集計に反映します。数量が未入力の案件数も確認できます。得意先・製品名・納期・数量・型・幅・配布担当の7列を印刷し、表示中の案件と並び順に合わせて、その印刷対象の担当別合計を表の下に付けます。A4縦1枚に自動縮小されるので、ブラウザの印刷設定はA4縦・倍率100％・ヘッダーとフッターをオフにしてください。納期未設定と削除済みの案件は月別表の対象外です。印刷しても製品ラベルの印刷待ち状態は変わりません。

## 製品ラベルを印刷する

メール・画像の読取結果を取込キューで確認して「案件へ反映」を押すと、その案件は自動で「ラベル印刷待ち」へ追加されます。ダッシュボードの待ち件数か「ラベル印刷」を開くと、待機中の先頭9件が選択された状態になります。選んだ順に、A4縦の上から1列9段で印刷します。各ラベルは横15cm×縦3cmです。

ラベルには、得意先、品名、全長、型、刃幅、注文番号（連番）、数量、納期を案件データから配置します。全長が`18cm`なら印刷時は`180`、`210mm`なら`210`としてmmの数値へ揃えます。品名の下のマーカーは納期月で色分けします。10月オレンジ、11月ピンク、12月緑、1月水色の4色を繰り返し、2月オレンジ、3月ピンク、4月緑、5月水色と続きます。プレビューと印刷で同じ色を使い、納期未設定の場合はマーカーを付けません。画面上でラベルを確認してから「○枚を印刷」を押してください。

ブラウザの印刷画面では、用紙をA4、向きを縦、倍率を100％にし、ヘッダーとフッターをオフにします。印刷画面から戻った後は、画面下部に固定表示される「印刷完了・待ちから外す」を押してください。印刷した案件が印刷済みになり、待ち一覧と件数から外れます。キャンセルや印刷失敗時は「キャンセル・待ちに残す」を選びます。ブラウザからは紙への印刷成功を判定できないため、印刷画面を閉じただけでは印刷済みにしません。

すでに印刷したラベルが待ちに残っている場合は、その案件だけを選んで「選択分を印刷済みにする」を押します。再印刷は不要です。印刷直後の確認対象は、検索・選択・表示範囲を変えても保持します。

印刷済み案件の得意先・品名・全長・型・刃幅・注文番号・数量・納期を変更すると、自動で「再印刷待ち」へ戻ります。工程・担当者・備考だけの変更では再印刷待ちになりません。既存表から移行した案件は勝手に待ちへ追加されず、案件編集画面の「製品ラベル」から必要なものだけ印刷待ちにできます。

プリンターやドライバーが自動縮小する場合があるため、最初の1枚は定規で横15cm×縦3cmになっていることを確認してください。

## Googleスプレッドシートへ接続する

詳しい手順は [導入手順](docs/導入手順.md) にまとめています。全体は次の順です。

1. 現在のスプレッドシートから「拡張機能 → Apps Script」を開く
2. このプロジェクトをビルドし、`dist`内のファイルをApps Scriptへ配置する
3. Apps Script上で `setupSystem` を1回実行する
4. Webアプリとしてデプロイする
5. アプリの「設定」で既存の月別シート名を指定して読み込む

アプリは元の月別シートを書き換えません。次の4シートを追加して使います。

- `工程管理_案件`
- `工程管理_取込キュー`
- `工程管理_設定`
- `工程管理_操作履歴`

## どこがサーバーになるか・誰が使えるか

画面はApps ScriptのWebアプリとしてPC・タブレットのブラウザで使います。Apps Scriptは所有者の権限で処理し、Googleスプレッドシートが共有データを保存します。別途レンタルサーバーを用意する構成ではありません。Webアプリの公開範囲はGoogleアカウントでログインした利用者とし、アプリ内の許可アカウント設定で利用者を制限します。所有者は常に管理者です。

所有者または管理者が「設定 → 利用アカウントと権限」でGoogleアカウントを追加し、アカウントごとに権限を選びます。スプレッドシートやApps Scriptエディタを共有する必要はありません。

| 権限 | できること |
| --- | --- |
| 閲覧のみ | 案件・工程・配布表の閲覧、検索、並べ替え、印刷。印刷済み状態は変更しません。 |
| 作業員 | 工程一覧・担当配布表・完成品リスト（出荷待ち・出荷済み）を利用します。工程の担当・状態と配布担当を更新でき、出荷待ち・出荷済み案件を閲覧できます。出荷完了・再開はできません。研磨への発送・戻り・履歴訂正を行う「研」ボタンと研磨管理表は利用できません。設定はこの端末の表示モードだけです。案件の追加・注文情報の編集・削除、取込キュー、APIを使う取込はできません。 |
| 編集者 | 従来の「編集のみ」と同じ権限。閲覧に加え、案件・工程・配布担当の更新、出荷待ちからの出荷完了・再開、研磨の発送・戻り・履歴訂正、手入力・ファイル・AIでの取込、取込キューの処理、印刷済み状態の更新。 |
| 管理者 | 編集に加え、利用アカウントと権限、工程・配布表の担当候補、共有設定の管理。 |
| 所有者 | 管理者の操作に加え、Gmail検索と検索式、AI診断、既存表の移行、初期設定、Apps Scriptの管理。 |

既存の「編集のみ」は自動的に「編集者」と表示され、権限は変わりません。作業員にしたいアカウントだけ管理者が権限を変更してください。指定済みの追加アカウントは「編集者」で登録されます。所有者は常に利用でき、変更・削除できません。管理者は自分自身の権限を下げたり削除したりできません。Gmail取込は従来どおりWebアプリ所有者のGmailを検索します。

Googleがログイン中のアカウントをアプリへ通知できる場合は、そのアカウントを自動確認します。通知されない場合は、許可済みアドレスへ届く8桁コードをアプリで入力します。コードは10分間有効で、5回まで試せます。再送は60秒後です。確認後の利用許可は最長7日間続き、Google側のセッション識別子が変わると再確認になります。パスワードや確認コードをCodexへ送らず、コードはWebアプリだけに入力してください。

初回は所有者が設定画面の「メール送信権限を確認」からGoogleの承認画面を開き、確認コード用のメール送信権限を許可します。リンクが表示されない場合はApps Scriptエディタで `getAccessSettings` を選び、一度実行してください。この確認は送信可能数を読むだけで、メールは送りません。許可後はWebアプリを再読み込みし、設定画面の送信権限に関する案内が解消したことを確認します。

独自ドメインの受信先がGoogle Workspaceなら、そのメールを直接検索できます。Google以外のメールサーバーで受信している場合は、注文メールだけをWebアプリ所有者のGmailへ自動転送して取り込みます。任意のメールサーバーへIMAP接続する機能は含めていません。

## ビルドとテスト

```powershell
npm.cmd run check
```

macOS・Linuxでは `npm run check` を実行します。

`dist/Index.html`へCSSとJavaScriptを内包し、Apps Scriptへ配置できる形を生成します。注文文面の解析、同時更新対策、UIの最低条件、文字コントラストも検査します。外部のフロントエンドライブラリや有料APIは使っていません。

```text
tools/               ローカル確認とApps Script用ビルド
tests/               注文文面パーサーとビルド規約のテスト

```

## 無料運用の前提

Googleスプレッドシート、Apps Script、Gmail、Google Driveの標準機能だけで動きます。追加のサーバー契約と有料OCR APIは不要です。独自ドメインメール側の契約料金や転送可否は、現在のメール事業者の条件に従います。またGoogleの無料枠には日次上限と1実行あたりの制限があり、大量のメールや画像を一括処理する用途では上限に達する可能性があります。現行値と注意点は [導入手順](docs/導入手順.md#無料運用と制限) を参照してください。


### 製品構成マスタと研磨代

工程一覧・完成品リストは表の上のタブで切り替えられ、23製品（簡易view）にも対応します。出荷待ちに入る案件と権限、研磨戻りの条件は上記のとおりです。
注文の製品番号を専用項目として保存し、製品構成マスタの番号・品名・寸法から使用材料を照合します。研磨管理表の区分を変更すると共有設定へ保存し、同じ製品と月別集計に反映します。編集者以上が区分を変更できます。曖昧な照合は要確認として残します。
編集者以上は研磨管理表で発送・戻りを記録し、履歴から直前の戻りや未返却分の発送を取り消せます。発送取り消しは研磨屋にある全数が対象で、数量入力は不要です。作業員には研磨管理表を表示しません。戻り訂正は発送日・発送数量を保ち、戻り数量と研磨屋の数量を修正して最終仕上げ待ちに戻します。元の戻りと取消記録は履歴に残り、取り消した戻りはその月の研磨代から除外します。出荷済みの案件は完成品リストで再開してから修正します。
研磨代は日本時間の戻り月で集計します。管理者は研磨管理表の「月別の研磨代」で月ごとの円/丁単価を入力・保存できます。未分類・単価未設定の数量を含む支払額は未確定です。0円と未設定は区別します。前月の単価は入力欄へコピー後、その月の値として保存します。
一覧にない特殊な製品は研磨区分「自由設定」を選び、江部・嘉代それぞれの円/丁単価を入力して「単価を保存」を押します。単価は製品ごとに共有設定へ保存され、同じ製品の次回案件にも反映します。月別研磨代では自由設定を研磨先・単価別に分け、対象製品も表示します。空欄は未設定、0円は有効な単価として扱います。編集者以上が設定でき、保存に失敗した入力は画面に保持します。「入力を戻す」で現在の保存値へ戻せます。
区分別数量と月別研磨代の表には「未分類」の固定欄を表示しません。区分・単価が未設定の製品も総数量と合計の要確認数量には含め、未確定の支払額を0円扱いにしません。
通常の製品は江部840円/丁と嘉代の区分別料金を別々に計算します。嘉代はA 2,000円、B 2,500円、B(メニスカス) 3,300円、C 3,000円、D 3,500円、特殊4,500円/丁です。区分「江部電解」は540円/丁、「江部磨き」は2,400円/丁を江部だけに計上し、通常840円と嘉代料金を加えません。製品名にメニスカス（半角カタカナも対応）がある製品は区分「B(メニスカス)」に自動判定します。研磨管理表で区分を変更すると保存され、同じ製品の次回と月別集計にも反映します。月ごとの保存済み単価を優先し、保存がない単価には上記の既定値を使います。
製品構成マスタは通常10分間キャッシュし、管理者の更新ボタンで再読込できます。読込失敗時は2026-10-06の組込データを使い、その旨を表示します。照合できた製品のラベルにはｱﾘｼﾞ・白銅・ｳｽｲを品名横へ追加します。
慈大式はC、全角・半角のY/TケリソンはDと判定します。倍力の特殊指定と保存した手動区分を優先します。田中の取込品名は末尾の`:JS07-040-4S-J`形式の補助番号や`TM対象`を除き、寸法・向きと製品番号を保持します。
ｱﾘｼﾞ・白銅・ｳｽｲは工程一覧の品名にも表示します。案件編集の「材料表示（一覧・ラベル）」で変更して注文情報を保存すると、同じ製品番号・得意先の次回案件にも反映します。品名へ直接追加した語も保存できます。材料表示欄を空にして保存するとマスタの自動表示に戻ります。別端末で材料表示が変わった場合は上書きせず確認を促します。

完成品リストは、上段に出荷待ち、下段に出荷済みを表示します。縦スクロールと倍率は共通で、検索と並び順はそれぞれに保持します。下段の出荷年月で絞っても、上段の出荷待ちには影響しません。碓井材料在庫の「発注・入庫一覧」は、全数入庫や残数取消の後も発注行を残し、各回の入庫日・数量と状態を同じ行で確認できます。
