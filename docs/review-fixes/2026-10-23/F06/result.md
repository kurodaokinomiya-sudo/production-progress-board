# F06 Tezoe在庫ダイアログの閉鎖

共通dialogハンドラーが在庫コントローラーの保護を迂回する指摘を確認した。背景/cancelの共通登録から在庫ダイアログを除外し、ボタン・背景・Escape・アプリ側の閉鎖要求を同じコントローラーのcloseへ集約した。保存成功と権限失効による強制終了もこの経路を使う。
通常の閉鎖は下書きと試行requestIdを保持し、pending中は拒否する。成功時は対象下書きを削除し、失効時は全下書きとフォーム内容を消す。失効前の遅い保存応答は、編集権限が復活しても復元しない。
表示は共通openDialogを使い、共通closeイベントでinert解除とフォーカスを復帰する。アクセス失効時はアクセス案内へフォーカスし、古い呼出元へ戻さない。既存の見た目・印刷・操作密度は変更しない。

在庫UI18テスト成功。3つの閉じ方それぞれで未編集/入力済/保存中/失敗後を確認し、応答消失の再試行と失効後の遅い成功/失敗も検証した。未保存確認・権限表示を合わせた関連49テストも成功。
`npm run qa:stock-dialog` はソース版・生成物で成功。実画面で数量5・備考の閉鎖/復元、遅い保存、3経路での失敗復旧、在庫履歴が1回だけ増えること、失効時強制終了、再許可後に下書きが出ないこと、キーボード・フォーカス・inert・768pxを確認した。
`frontend-design` と最新のWeb Interface Guidelinesで変更範囲を確認し、タブレットのPNGも視認した。
