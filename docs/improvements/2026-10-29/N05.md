# N05 Node対応範囲と再現手順

## 宣言と根拠

修正前の `package.json` はNode.js `>=20` と宣言していた。固定の `pdfjs-dist@6.3.289` の `engines.node` は `>=22.13.0 || >=24` であり、宣言の下限が一致していなかった。開発サーバーは `tools/local-pdf-parser.mjs` を経由してPDF.jsを静的importする。Node.js 20での実クラッシュは確認していない。

本プロジェクトの対応範囲は22.13.0以降の22系または24以降とし、`package.json` と `package-lock.json` ルートの `engines.node` を `^22.13.0 || >=24` に揃えた。推奨は24系。23系の除外はプロジェクトの対応方針であり、PDF.jsの宣言そのものが23系を拒否するという意味ではない。

READMEとブラウザーQA手順も同じ下限・推奨環境・検証範囲へ更新した。依存バージョン、GASランタイム、clasp接続先、公開URLは変更していない。

## 確認環境と隔離コピー

- Windows x64、OS build 26300、Node.js v24.19.0、npm 11.6.2。
- `output/improvements-2026-10-29/n05-isolated/` にプロジェクト137ファイルをコピー。`.git`、`.clasp.json`、`.env`、既存`output`、既存`node_modules`は含めていない。
- コピー日時・元HEAD・各ファイルSHA256を `output/improvements-2026-10-29/n05-snapshot.json` に記録した。N03/N06統合後、ソースを固定して138ファイルを再同期し、2026-10-29 06:53 UTC時点の各SHA256を `n05-final-snapshot.json` に記録した。
- npmのcacheも同じ作業用output内に専用作成した。手順自体は個人ホームやCodex内部ランタイムの固定パスを必要としない。

## 実行結果

- 隔離コピーで `npm ci` とビルドを実行した。
- 最初の `npm ci` は終了0だったが、optionalの `@napi-rs/canvas` が導入されず、Nodeの探索が親checkoutの依存へ到達した。この状態は新規導入の成功証拠として採用しなかった。
- 固定の `@napi-rs/canvas@1.0.8` tarballが公式npm registryからHTTP 200で取得できることを確認し、専用cacheから `npm ci --offline` を再実行した。5パッケージの導入が成功し、`createRequire.resolve` でPDF.js、Playwright、canvas、Windows x64 native canvasのすべてが隔離コピー自身の `node_modules` 内にあることを確認した。初回失敗をNode版やパス長の問題とは断定していない。
- `node --test --test-isolation=none tests/local-pdf-extraction.test.mjs` 成功。実際のPDF.jsをimportし、xrefを持つ合成1ページPDFから `N05 PDF text 123` を抽出した。実帳票や文字なし画像の認識を検証したものではない。
- `node tools/browser-smoke.mjs` 成功。隔離コピー自身の専用localhost devサーバーを起動して、正規build後のsource/dist双方で主要画面・注文保存と再読込・工程保存と再読込・タブレット表示を確認した。N03/N06統合後の最終証跡は隔離コピーの `output/browser-qa/smoke-2026-10-29T06-53-27-571Z/`。
- 初回コピー時点の全テストは883件中877成功、6失敗。失敗はN03で追加した権限再確認回数を旧spy期待が許容しないケースであり、Node導入の失敗とは区別した。N03側でロック内の再確認を意味として検証する回帰へ改善した後、最終コピーで全905件成功を確認した。PDF実抽出もこの全体実行に含む。
- `git diff --check` 成功。packageとlockの変更はルートのNode宣言だけで、依存バージョン・解決先・integrityの変更なし。

個別ログは `output/improvements-2026-10-29/n05-*.log`、宣言と実環境の比較は同ディレクトリの `n05-environment.json` に残した。

調査中、sandboxと昇格実行のTemp可視性の違いで作業ディレクトリ移動が失敗し、元checkoutの同一lockも一度再導入した。`node_modules` の再生成のみで、ソース・依存版の変更はない。以後は実在確認済みの絶対作業ディレクトリを指定し、上記の最終検証を隔離コピーで完了した。

## 他環境での再現

個人設定・認証ファイル・既存依存を含まないcheckoutまたはCIで、リポジトリルートから実行する。Windows PowerShellでは `npm` を `npm.cmd` に読み替える。

```sh
node --version
npm --version
npm ci
npm run build
node --test --test-isolation=none tests/*.test.mjs
npm run qa:install
npm run qa
```

PDF抽出だけを再確認する場合は以下を実行する。

```sh
node --test --test-isolation=none tests/local-pdf-extraction.test.mjs
```

`npm run qa` は専用devサーバーを起動・終了するため、手動のサーバー起動は不要。手動で画面を開く場合は `npm run dev` と表示されたlocalhost URLを使う。
