# N03 — ロック取得後の最新権限確認

ロック待機中に利用者が降格・削除された場合、取得後に必要権限を再確認してから正規データ・在庫イベント・監査を書きます。工程・配布担当は最新のworker権限を使い、出荷や完成済み案件の編集には引き続きeditor権限を要求します。共通のScriptLock、owner固定、既存の認証フローを維持します。

## 修正前の再現

`output/improvements-2026-10-29/boundaries-before.log` は実AccessControl関数と合成Session/Properties/lockを使用。editorで工程保存を開始し、`waitLock()`内でviewerへ降格させても、工程done・version2が保存されることを確認しました。本番アカウントや設定は変更していません。

## 入口照合

|必要権限・境界|公開入口と保護する内部境界|確認結果|
|---|---|---|
|worker|`saveJobProcess`, `setDistributionAssignee`|Repositoryのlock内でaccess再取得。最新canEditを工程・出荷・配布・返却データに使用|
|editor|`saveJob`, `setJobArchived`, `markLabelsPrinted`, `approveIntake(s)`, `rejectIntake(s)`|Repositoryの保存callbackで再確認。個別の取込操作は保護された一括入口へ委譲|
|editor|`saveMaterialOrder`, `receiveMaterialOrder`, `adjustMaterialStock`, `cancelMaterialOrder`|Materialsの`mutateMaterials_`で再取得し、actorへ使用|
|editor|`receiveFinishedStock`, `shipFinishedStock`, `openFinishedStock`, `reverseFinishedStock`, `saveFinishedStockSchedule`|FinishedStockの`mutateFinishedStock_`で再取得し、actorへ使用|
|editor|`savePolishingMovement`, `savePolishingEventDate`, `savePolishingProductRule`, `forgetIntakeLearningRule`|各lock callbackで再確認。製品設定の応答も最新accessを使用|
|editor|`createIntakeFromImage`, `createIntakeFromPdfText`, `createIntakeFromText`, `createIntakeWithAi`|OCR/解析/AIはlock外。`saveParsedIntake_`のlock内で再確認し、取込監査も同じ区間で保存|
|admin|`saveSettings`, `saveCustomerRules`, `savePolishingRates`, `refreshProductMaster`|各lock内で再確認。製品マスター外部取得はlock外、既存cacheの公開とミラー更新はlock内|
|owner|`setupSystem`, `migrateLegacySheet`, `scanOrderEmails`|setup/移行/メール候補保存・監査で再確認。Gmail設定キーの保存時もownerを再確認|
|editor / owner|AI使用量の保存`sendAiRequest_`|通常取込はeditor、診断・メールはownerをlock内で確認。外部AI呼出はlock外|
|read + editor repair|`getMaterialInventory`, `getFinishedStock`|材料初期数量のseed・在庫履行の再整合より前にeditor再確認|
|read + current app access|`getSnapshot`, `repairPolishingMirrorIfNeeded_`|待機中降格後のsnapshotは最新権限で返却。viewerに材料seedをせず、取込/AI/編集者設定を返さない。派生ミラーの保守repairはviewerにも許可し、削除された利用者には実行しない|
|authentication / admin|`requestAccessCode`, `verifyAccessCode`, `rememberAccessDevice`, `restoreAccessSession`, `saveAccessSettings`|AccessControlの既存lock内allowlist/権限/端末再確認を維持。確認コード送信はlock外|

`setupSystem`の初期化には既存lockを引き渡し、pending mirror repairが二重取得しないようにします。通常のマスター読取時の派生cache補充は従来の読取処理のままです。共有cacheの新設やデータ保存形式の変更はありません。
