# 碓井材料在庫管理

「碓井材料在庫」は、管理者・編集者・所有者が利用できます。作業員・閲覧のみの利用者には表示せず、サーバーでも材料の閲覧・更新を制限します。

## 開始時の在庫と対象

2026年10月20日に提供された在庫画像の最終値を開始残高とします。本体とカブセを合わせた、製品1丁分を1セットとして数えます。

| 材料 | 型・向き | 開始在庫 | 対応する製品番号 |
| --- | --- | ---: | --- |
| CK001 共通材料 | 直・上向 | 28セット | 慈大式 CK001、Tezoe 26001 |
| CK011 共通材料 | 弱弯・上向 | 12セット | 慈大式 CK011、Tezoe 26011 |
| CK002 慈大式材料 | 直・下向 | 42セット | 慈大式 CK002 |
| Tezoe 26002 専用材料 | 直・下向 | 1セット | Tezoe 26002 |
| CK021 共通材料 | 強弯・上向 | 0セット | 慈大式 CK021、Tezoe 26021 |
| CK022 共通材料 | 強弯・下向 | 0セット | 慈大式 CK022、Tezoe 26022 |

Tezoeは同じ曲がり・向きの慈大式材料を使い、直・下向の26002だけ独立した在庫を使います。弱弯・下向（慈大式 CK012、Tezoe 26012）は現在この表の材料を使わないため、材料使用数の計算と「要確認」の対象から除外します。製品番号がなくても、対象製品の型・向きが弱弯・下向と確定していれば同じ扱いです。製品番号と型・向きの不一致や曖昧な指定は、引き続き確認が必要です。未登録の型・向きや別の仕入先の製品は、自動で他の材料に置き換えません。

## 注文との連動

手入力で案件を保存したとき、または取込キューの注文を個別・一括で確定したときに、対象製品の数量を碓井材料在庫から差し引きます。取込候補の作成・確認中・却下・重複拒否では減りません。同じ保存・承認を再試行しても、二重に減りません。

開始前から存在する案件は、画像の在庫に反映済みとして扱い、さかのぼって差し引きません。その案件の数量や材料を変更した場合は、変更分だけ反映します。製品番号・型・向き・数量から材料を特定できない案件は「要確認」に残るため、案件を開いて注文内容を確認してください。

在庫が足りなくても注文は登録できます。在庫数がマイナスになり、不足数を目立つ色で表示します。発注中の数量は現在庫と別に表示し、入庫した時点で現在庫へ加算します。

## 発注・入庫の操作

1. 材料を選んで「発注」を開き、発注日・発注数・入庫予定日を入力して記録します。
2. 「発注・入庫一覧」で未入庫数と予定日を確認します。入庫待ち・一部入庫の発注を先に、入庫済み・取消済みの発注をその下に表示します。
3. 納品された発注の「入庫を記録」を開き、実際の入庫日・入庫数を記録します。一部入庫にも対応し、発注した行の「入庫日・数量」に今回分を追加します。
4. 現在庫が入庫数だけ増え、発注残は同じ数だけ減ります。発注残を超える入庫は登録できません。全数の入庫後も同じ発注行を残し、分納した場合は各回の入庫日と数量を確認できます。実日付の履歴がない過去分は「日付不明」と表示し、予定日を実日付として扱いません。
5. 未入庫分を取り消すときは、その発注の「残数を取消」で理由を記録します。すでに入庫した在庫は減りません。発注行には取消の状態と数量を残し、入庫済み分の実績も保持します。

## 履歴・棚卸し

履歴には開始残高、発注、入庫、案件への材料引当、注文変更による引当解除、在庫調整、発注残の取消を残します。材料・操作の種類で絞り込み、品名・得意先・連番などで検索できます。

「入出庫・発注の履歴」も、発注1件とそれに続く入庫・取消を同じ1行にまとめます。発注日・発注数と、各回の入庫日・入庫数、発注残を横並びで確認できます。分納や全数入庫の後も1行のまま残し、それぞれの備考・記録者も保持します。「入庫」で絞ると入庫記録がある発注行が表示され、入庫時の備考・記録者で検索しても、その発注の履歴全体を確認できます。開始残高・案件引当・在庫調整などは従来どおり個別に表示します。

案件を出荷完了にしたり、一覧から削除・復元したりしても、材料の実物が戻ったとは判断せず、在庫を増やしません。材料を実際に戻す場合や棚卸しの差異は、「在庫調整」で増減数と理由を記録してください。誤った入庫の在庫数を直す場合も、調整理由に元の入庫を記録して履歴を残してください。

保存中は同じ操作を重ねて実行できません。通信に失敗した場合は入力を残し、同じ内容で再試行できます。

金額・単価の入力と原価集計は今回の対象に含みません。発注・入庫・使用の識別情報を保存するため、今後のコスト管理の追加に利用できます。
