# 導入手順

## 1. 先にバックアップする

アプリは既存の月別シートを変更しませんが、初回移行前にスプレッドシートを複製しておくと安全です。「ファイル → コピーを作成」でバックアップを作ります。

## 2. Apps Scriptプロジェクトを準備する

1. 現在の進捗表をGoogleスプレッドシートで開く
2. 「拡張機能 → Apps Script」を開く
3. 左側の「プロジェクトの設定」を開き、スクリプトIDを控える
4. このフォルダでビルドする

```powershell
& "C:\Program Files\nodejs\npm.cmd" run check
```

### CLIで配置する方法

Google公式の`clasp`を使うと、複数ファイルをまとめて配置できます。

```powershell
& "C:\Program Files\nodejs\npx.cmd" --yes @google/clasp login
Copy-Item -LiteralPath ".clasp.json.example" -Destination ".clasp.json"
```

`.clasp.json`を開き、`scriptId`を手順3で控えたIDへ置き換えます。その後、次を実行します。

```powershell
& "C:\Program Files\nodejs\npx.cmd" --yes @google/clasp push
```

### Apps Scriptエディタへ手動で貼り付ける方法

GoogleログインやCLIを使わない場合は、次の対応で1ファイルずつ貼り付けます。`.gs`とHTMLは種類が違うため、同じファイルへまとめないでください。

| Apps Script側 | 作成方法 | 貼り付けるファイル |
| --- | --- | --- |
| `コード.gs`（最初からあるスクリプト） | 既存ファイルを開く | `dist/Code.gs` |
| `Config.gs` | 「＋ → スクリプト」、名前は `Config` | `dist/Config.gs` |
| `Import.gs` | 「＋ → スクリプト」、名前は `Import` | `dist/Import.gs` |
| `Parser.gs` | 「＋ → スクリプト」、名前は `Parser` | `dist/Parser.gs` |
| `Repository.gs` | 「＋ → スクリプト」、名前は `Repository` | `dist/Repository.gs` |
| `Index.html` | 「＋ → HTML」、名前は `Index` | `dist/Index.html` |

特に、`dist/Index.html`を`コード.gs`へ貼り付けてはいけません。`コード.gs`の1行目が `<!doctype html>` になっていると、保存時に「`Unexpected token '<' 行: 1`」になります。その場合は`コード.gs`の内容をすべて`dist/Code.gs`へ入れ替え、HTMLは「＋ → HTML」で作った`Index.html`へ貼り直します。

`appsscript.json`は「プロジェクトの設定 → マニフェスト ファイルをエディタで表示する」を有効にしてから、`dist/appsscript.json`の内容へ置き換えます。すべて保存した後に手順3の`setupSystem`を実行します。すでにウェブアプリを公開していた場合は、修正後に「デプロイ → デプロイを管理 → 編集 → 新バージョン」で更新してください。

## 3. 初期シートを作る

Apps Scriptエディタ上部の関数選択で `setupSystem` を選び、「実行」を押します。初回のみGoogleの権限確認が表示されます。

成功すると、元の進捗表と同じファイルに次の4シートが追加されます。

- `工程管理_案件`
- `工程管理_取込キュー`
- `工程管理_設定`
- `工程管理_操作履歴`

既に同名のシートがあり、見出しがアプリ形式と違う場合は自動上書きせず停止します。旧版のアプリ用シートには、今月完了を集計する `completedAt` 列と大分類の `category` 列を末尾へ追加します。既存列の順序とデータは変更しません。

## 4. Drive OCRを有効にする

`appsscript.json`にはDrive APIを使う設定が入っています。画像読取時に「Drive OCRを開始できません」と表示された場合は、Apps Scriptエディタ左側の「サービス」から `Drive API` を追加してください。

画像とPDFはOCR用の一時Googleドキュメントへ変換し、文字を取得した後にその一時ファイルを削除します。アップロード元画像はアプリ側では保存しません。メール添付の原本はGmailに残ります。

## 5. Webアプリとして公開する

1. Apps Script右上の「デプロイ → 新しいデプロイ」
2. 種類に「ウェブアプリ」を選ぶ
3. 「次のユーザーとして実行」は自分（スプレッドシート所有者）を選ぶ
4. 1人でPC・タブレットから使う場合は、同じGoogleアカウントだけがアクセスできる設定にする
5. 同じGoogle Workspace内の複数人で使う場合は、組織内だけに限定する。この場合、Gmail検索は手順3で指定した所有者の受信箱を対象にする
6. 発行されたURLをPCとタブレットで開く

匿名アクセスは使わないでください。注文情報とGmailを扱うため、公開URLにする構成は想定していません。

この構成では、Apps ScriptがGoogle上のバックエンド、スプレッドシートが共有データベースに相当します。PCとタブレットは同じWebアプリURLを開くだけで、保存内容は同じスプレッドシートへ入り、20秒ごとに再同期されます。テーマ設定だけは各端末に保存されるため、PCをダーク、タブレットをライトにすることもできます。

## 6. 現在の表を読み込む

1. Webアプリの「設定」を開く
2. 「現在の管理表を読み込む」に月別タブ名（例：`2026.7`）を入力
3. 「既存表を読み込む」を押す
4. 「案件」で件数と内容を確認する

得意先、品名、大分類、納期、数量、全長、型、刃幅、連番、溶接、元作り、浮き止め～立ち上がり、厚みとり、仕上げ、備考、出荷状況の見出しを照合します。大分類は「分類」「製品分類」、刃幅は「刃巾」も互換名として扱います。旧工程名の「元づくり」「すり上げ」「焼なとり」「仕上」も読み込めます。元シートの行番号を記録するため、同じシートをもう一度読み込んでも重複登録しません。

品名に「ケリソン」「スタンツェ」「スタンチェ」「彫骨器」が含まれる場合は `ケリソンパンチ`、「鉗子」が含まれる場合は `鋭匙鉗子` を大分類へ補完します。ケリソン系の語は「鉗子」より先に判定するため、「ケリソン鉗子」は `ケリソンパンチ` になります。品名中の `18cm`、`全長120mm`、`2mm`、`刃幅3.5mm` なども、対応する仕様欄が空の場合だけ補完します。判定できない値は空欄のまま取込キューで確認します。

現在表の工程欄に独自の略号がある場合、空欄は「未着手」、`済`・`完`・末尾の`研`を含む値は「完了」、`保留`・`止`・`待`を含む値は「保留」、それ以外の入力済み値は「進行中」として移行します。移行後に数件を目視確認してください。

## 7. 注文メールを取り込む

### 独自ドメインをGoogle Workspaceで受信している場合

独自ドメインのMXレコードがGoogle Workspaceを向き、Gmail画面でその受信箱を使っている場合は、そのまま検索できます。Webアプリは手順5で指定した所有者のGmailを読みます。

### Google以外のメールサーバーで受信している場合

レンタルサーバー、ZohoなどGoogle以外で受信している場合、このアプリから任意のIMAPサーバーへ直接接続はしません。メール事業者側で注文メールだけをWebアプリ所有者のGmailへ自動転送してください。Gmailで転送メールに `受注転送` などのラベルを付け、検索式を次のようにすると誤取込を減らせます。

```text
label:受注転送 newer_than:30d
```

自動転送の可否や追加料金は、現在契約しているメール事業者で確認してください。

初期のGmail検索式は次です。

```text
newer_than:30d (subject:(注文 OR 発注 OR 依頼))
```

自社のメール件名に合わせ、Webアプリの「設定」で送信元やラベルを追加します。直接受信している場合の例：

```text
newer_than:30d from:orders@example.jp (subject:(注文 OR 発注))
```

「注文を取り込む → メールを探す」を押すと、候補を「取込キュー」へ追加します。メールは削除・移動・既読化しません。同じGmailメッセージIDは二重登録しません。

## 8. 注文画像を取り込む

「注文を取り込む → 画像を選ぶ」から、JPEG・PNG・WebP・PDFを選びます。画像はブラウザ側で長辺2,000pxへ縮小し、OCRへ送ります。読取結果は必ず取込キューで確認してから案件へ反映します。

田中医科の `TC_26_1790` 形式のように1枚へ複数品目が並ぶPDFは、品目番号ごとに取込候補を分割します。購買Noは `26-1790-1` のような連番へ、各列の希望納期と数量は対応する品目へ再結合します。半角カナと `㎜`・`㎝` も正規化し、品名に含まれる全長・刃幅・型・大分類を補完します。品目番号の飛びや数量未読取がある結果は保存しません。ローカル版では旧解析エンジンの確認待ち候補を自動除去し、同名PDFの再取込時は前回候補を置換します。

ローカルWebアプリは `npm run dev` で起動した場合に、文字が埋め込まれたPDFをPDF.jsで直接解析します。解析コードを更新した後は起動中のサーバーを停止し、`npm run dev` を再実行してください。画面と解析サーバーの版が異なる場合は取込を止めて再起動案内を表示します。HTMLファイルを単体で開いた場合は解析APIがないため動作しません。スキャン画像や写真だけのPDFは、Google Drive OCRを利用するApps Script版で確認してください。

明るい場所で、紙面を正面から、文字が潰れない距離で撮ると読み取りやすくなります。手書き文字や斜め撮影、罫線の多い表では空欄や誤読が起きるため、確認工程は省略しないでください。

## 9. 製品ラベルをA4へ印刷する

1. メール・画像の読取結果を取込キューで確認し、「確認して案件へ反映」を押す
2. 自動で「ラベル印刷待ち」へ入ったことをダッシュボードの件数で確認する
3. 「ラベル印刷」を開く（待機中の先頭9件が自動で選択されます）
4. 得意先、品名、全長、型、刃幅、注文番号、数量、納期のプレビューを確認する
5. 「○枚を印刷」を押す
6. 印刷画面で用紙をA4、向きを縦、倍率を100％にする
7. ブラウザのヘッダーとフッターをオフにして印刷する
8. 印刷画面から戻り、正常に印刷できた場合だけ「印刷済みにする」を押す

ラベルは1枚あたり横15cm×縦3cmです。9枚選ぶとA4縦の上から1列9段、高さ270mmで配置され、上下は13.5mmずつ空きます。全長は`18cm`を`180`、`210mm`を`210`のようにmmの数値へ揃えて表示します。型や刃幅などが未入力の場合は`—`になるため、案件編集画面で修正してから印刷してください。

プリンターの設定に「用紙に合わせる」「自動縮小」がある場合は無効にします。初回は印刷後に定規で寸法を測り、横15cm×縦3cmになっているか確認してください。ずれる場合は、まず印刷倍率が100％かを確認します。

「印刷済みにする」を押すまでは印刷待ちのままです。印刷をキャンセルした場合や紙詰まりなどで印刷できなかった場合は、「まだ印刷していない」を押してください。印刷済み案件の得意先・品名・全長・型・刃幅・注文番号・数量・納期を変更すると、自動で「再印刷待ち」へ戻ります。工程・担当者・備考だけの変更では戻りません。

既存の月別表から読み込んだ案件は、導入直後に大量の印刷待ちを作らないため「ラベル不要」で登録されます。必要な既存案件は、案件編集画面の「製品ラベル」を「印刷待ち」へ変更してください。印刷画面の表示範囲を「印刷済み」または「すべての進行案件」に切り替えると、履歴確認や再印刷もできます。

## 無料運用と制限

この構成は追加のサーバー代や有料OCR APIを必要としません。Google Apps Scriptの上限は変更される可能性があります。2026年7月22日更新のGoogle公式表では、個人Googleアカウントの代表値は次のとおりです。

- Gmailの読取／書込（送信を除く）：20,000回／日
- ファイル変換：2,000件／日
- 1回のスクリプト実行：6分
- 同一ユーザーの同時実行：30
- 1メッセージの添付合計：25 MB

通常の少人数・日々の注文処理では十分余裕のある構成ですが、数百通・数百画像を一度に読み取る運用には向きません。メール検索は1回20スレッド、画像OCRはメール1通につき添付3件までに抑えています。

Apps Scriptの上限は [Google公式のクォータ表](https://developers.google.com/apps-script/guides/services/quotas) で確認できます。Webアプリの権限と公開範囲は [Google公式のWebアプリ手順](https://developers.google.com/apps-script/guides/web) を参照してください。

## 日常運用

- 画面を開いたままにすると20秒ごとにデータを再読込します。
- 保存直後は待たずに画面へ反映し、裏側の保存に失敗した場合だけ元の表示へ戻します。
- 同じ案件を別端末で先に保存した場合、古い画面からの上書きを止めます。画面を更新して差分を確認してください。
- 各案件の編集画面で、溶接・元作り・浮き止め～立ち上がり・厚みとり・仕上げそれぞれの担当者を、豊・幹・望・鈴・河・誠・小・保・大・順の10名からボタンで選択します。担当プルダウンを開くと10名全員が表示され、ダッシュボード、一覧、検索へ反映されます。
- 一覧の「現在工程」を押すと工程専用画面が開きます。日常の工程完了・保留・担当変更では注文情報を開く必要はありません。鉛筆ボタンは、得意先・品名・数量・仕様などを変更するときだけ使います。
- 5工程をすべて完了すると案件は「出荷待ち」になります。工程専用画面の「出荷完了・終了へ」を押すと進行中の一覧から外れて終了リストへ移動します。誤って終了した場合は、終了案件の工程画面から「進行中へ戻す」で出荷待ちへ戻せます。
- 誤登録した案件は注文情報画面の「案件を削除」で一覧から外せます。直後に表示される「元に戻す」で復元できます。スプレッドシートの行は物理削除せず、削除・復元を操作履歴へ記録します。
- 「今月完了」は、「出荷完了・終了へ」で終了リストへ移した時刻で集計します。「進行中へ戻す」で出荷待ちへ戻した案件は集計から外れ、もう一度出荷完了にすると、その時点の月へ入ります。
- 移行前の表には完了日時がないため、既に完了していた過去案件は推測で今月へ加えません。導入後に完了した案件から正確に集計します。
- 「設定 → 表示テーマ」で端末設定に合わせる、ライト、ダークを選べます。選択は端末ごとに保存され、案件データには影響しません。
- メール・画像から確認反映した案件は自動でラベル印刷待ちになります。「ラベル印刷」では待機中の先頭9件が自動選択され、選択順がA4縦の上からの印刷順になります。
- 印刷後は「印刷済みにする」を押して待ち一覧から外します。ラベル内容を変更した印刷済み案件は自動で再印刷待ちになります。
- `工程管理_操作履歴`に、作成・更新・取込・設定変更の時刻と対象IDを記録します。

## 困ったとき

### 「別の端末で先に更新されています」

「更新」を押し、相手の変更を確認してからもう一度編集します。

### Gmail検索で権限エラーになる

Apps Scriptエディタで `scanOrderEmails` を一度実行し、Gmail読取権限を許可してからWebアプリを再読み込みします。

### 画像から文字を検出できない

Drive APIが有効か確認し、画像を明るく正面から撮り直します。PDFが大きい場合は必要なページだけに分け、8 MB以下にします。

### Webアプリに変更が反映されない

Apps Scriptは既存デプロイへ新バージョンを割り当てる必要があります。「デプロイ → デプロイを管理 → 編集」から新しいバージョンを選び、デプロイし直します。
