# 無料枠のAI注文取込

## 最初に1回だけ必要な設定

1. [Google AI StudioのAPIキー画面](https://aistudio.google.com/api-keys)で、専用プロジェクトのプランが **Free Tier** であることを確認します。請求先アカウントは紐づけず、「Set up billing」「有料へアップグレード」は押しません。
2. そのプロジェクトのAPIキーを作成します。キーはチャット・スプレッドシート・ソースコードへ貼らないでください。
3. アプリの「設定」→「Apps Scriptを開く」を押します。別タブで開いた先の歯車「プロジェクトの設定」→「スクリプト プロパティ」に以下を保存します。編集権限のあるGoogleアカウントでログインしてください。

| プロパティ | 値 |
|---|---|
| `GEMINI_API_KEY` | 作成したAPIキー |
| `AI_FREE_TIER_CONFIRMED` | Free Tierを確認した後に `true` |
| `AI_DAILY_LIMIT` | 任意。未設定なら1日10回。1〜100の範囲 |

4. アプリを再読み込み。「注文を取り込む」に「AI設定済み」と表示されます。

プロパティの変更だけなら再デプロイは不要です。各PC・タブレットへのキー設定も不要です。無効にする場合は `AI_FREE_TIER_CONFIRMED` を `false` にします。

**アプリはGoogleの請求設定を確認・変更しません。** `AI_FREE_TIER_CONFIRMED` は管理者による確認の記録です。有料プロジェクトのキーを設定すればAPI料金が発生し得ます。無料維持の条件はキーの所属プロジェクトをFree Tierのままにすることです。

無料枠の入出力はGoogleの製品改善に使われる場合があります。個人情報・機密情報を含む資料は送信しないでください。

## 使い方

- 「読取方法」で「AIで読む」を選び、PDF・JPEG・PNG・WebPを読み取ります。PDFはテキスト化で列を崩さず、原本をAIへ送ります。画像は既存の画面側リサイズを行います。
- キー設定済みならAIが初期選択です。「従来の読取」を選べばAIへ送信しません。エラー時に従来方式や別モデルへ勝手に切り替えません。
- 独自ドメインメールは、従来どおり接続先Gmailへ転送されたものを検索します。AIでは未取込メールを1通ずつ処理。10秒以上あけて再度検索すると続きへ進みます。検索は直近の検索結果20スレッドです。
- 添付は1回あたり最大3件、合計8 MB。非対応の添付や件数超過は捨てずに停止します。手動アップロードは1ファイルずつです。
- 「AI・要確認」の候補に、原本のページ・行、AIが引用した根拠、確認事項が表示されます。原本自体はこの機能では保存しません。元のPDFやメールを別途開いて照合してください。
- 全件数・数量合計の矛盾、重複行、回答の打切りは候補を登録せず停止。数量不明は空欄で確認に回し、数量を入力するまで承認できません。
- 数量・納期・仕様・全明細が揃っているかを人が確認してから案件へ反映します。承認後は既存どおり印刷待ちに入ります。
- 品名前の製品コード（例：`F06-35-30L`、`06-56-60S`）は品名へ含めず、備考に「品番: …」として残します。AIが先頭へ付けた場合も、回答の検証時に分離します。品名内の型番（`JS07-040-6L`など）、寸法、向きは保持します。次回の取込から適用し、既存の案件を一括変更する処理は行いません。

## 得意先の判定と修正

「設定」または「まとめて確認・編集」の「得意先の読取ルール」で、御社名と発注元の表記を管理できます。初期ルールは「有限会社 興之宮医科工業」を得意先から除外し、「ミズホ株式会社」「ミズホ株式会社 五泉工場」を「ミズホ」、「田中医科器械製作所」を「田中」に揃えます。発注元の会社名が一致した場合だけ適用し、注文書にミズホという語があるだけでは置き換えません。AIが御社名を得意先として返した場合は空欄と確認事項を残します。

取込候補を一括編集するときは、対象の品目にチェックを付け、「得意先をミズホにして」と入力して「変更内容を確認」を押します。表示された件数と変更前後を確認し、「この内容で修正」を押すと選択した品目だけが変わります。品名・数量・納期は変更しません。この入力欄は得意先の修正専用です。

「次回のAI読取にも適用する」は初期状態でオフです。オンにする場合は、注文書に書かれた発注元の正式名を入力してください。御社名をミズホへ変換するようなルールは保存できません。修正した注文は、従来どおり「案件へ反映」で確定します。途中の編集は同じページ内で保持しますが、再読み込みでは破棄されます。

読取ルールは保存後、他の端末や次回のAI取込でも使います。ルール画面から対応の変更・削除ができます。同時更新時は上書きせず、入力内容を残して読み直しを案内します。既存の案件や候補にはさかのぼって適用しません。ローカル版のルールはそのブラウザの確認用データに保存し、本番とは共有しません。

機能確認は `tools/customer-rules-qa.mjs`、判定・永続化の検証は `tests/customer-rules.test.mjs` と `tests/local-customer-rules.test.mjs` です。実注文書をGeminiに送っての読取精度は別途確認が必要です。

## 上限と限界

- 回答はシンプルなJSON出力を指定し、必要な構造は指示文で伝えます。Google側への`responseJsonSchema`指定は送信しません（最小通信成功・従来の回答形式診断400の切り分けを受けた回避修正）。項目の型・必須値・数量合計・明細数などのアプリ側検証は維持します。Google側が構造を強制する方式ではないため、不正な回答は候補登録前に停止します。この修正の本番での効果は再診断・実注文書で別途確認が必要です。

- 「AIで読み取れないとき」→「注文書を送らず接続診断」で、固定テスト文による最小限の通信・アプリの回答形式を順に確認できます。10秒以上あけて最大2回、同じモデルへ送信し、通常のAI日次上限に数えます。失敗すると後続テストは送信せず停止。実注文書は送信せず、診断データを案件・取込候補に保存しません。両方成功してもPDFの読取成功は未確認です。1番目で失敗すれば接続・キー・モデル利用条件など、1番目が成功し2番目で拒否されればアプリの追加設定などを次に調べます。一時的な障害もあり得るので、結果だけで原因を断定しません。

- HTTP 400などの失敗時は、取込画面に診断コードと「Google応答」が残ります。UNKNOWNでも理由の本文と不正な項目名を確認できます。APIキー・入力本文・ファイル名との完全一致、URL、メールアドレス、長い値は伏せ、応答メタデータは表示しません。部分的な引用までは除去できないため、共有前に注文情報が残っていないか確認してください。診断は拒否応答の分類であり、取込成功を保証するものではありません。地域・無料枠の条件が理由でも有料化や接続元の迂回は行いません。

- 429応答（上限・混雑）はその場で停止し、自動再試行・有料プラン変更・別モデルへの切替は行いません。
- アプリ独自の上限は日本時間で1日10回が既定。失敗した送信も回数に含めます。Google側の上限を示す数値ではなく、実際の利用可能数はGoogle AI Studioで確認してください。
- モデルは `gemini-3.1-flash-lite`。APIキーはサーバーにのみ保存し、ブラウザには設定の有無だけを返します。
- 件数や根拠の引用もAIの出力です。整合チェックは誤読や末尾明細の欠落を完全には検知できません。読取精度のパーセントは表示しません。
- キー未設定時は従来機能だけ利用できます。実注文書での精度確認には、API設定後に田中医科の別注文書と他社書式で照合が必要です。

## ローカル確認用

起動するサーバーの環境変数に `PROGRESS_GEMINI_API_KEY` と `PROGRESS_AI_FREE_TIER_CONFIRMED=true` を設定します。任意の上限は `PROGRESS_AI_DAILY_LIMIT`。秘密情報を含む起動コマンドをチャットへ貼らないでください。環境変数はサーバー再起動で反映されます。

ローカル版もApps Scriptのリクエスト生成・応答検証コードを共用します。ローカルの回数カウントはプロセス内のためサーバー再起動でリセットされます。実運用はApps Script版を使ってください。
